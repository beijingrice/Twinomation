## 以现有业务规则为准的整合

- 朋友的持续跟进/延误统一落在现有“延误或时间待确认”的发布模型；不复制绕开工单资源审核的直接发布路径。
- 正常运行状态新增 `ON_TIME`，与登机/延误同样经 OCC 工单授权。航站楼也是 OCC 授权后的公开字段。
- 地面任务“已完成”不自动等于正式工单资源“已就绪”；仍需外站回复、OCC 审核。
- 召回、通知和旅程发布均遵守全局发布暂停。取消航班作废排程及召回。新一轮工单清除旧召回。
- 后续航班仍按用户的 **≤30分钟红、>30且<60黄、≥60绿**；不采用朋友的45/120分钟规则。
- 保留原有35城双语指南、温柔问答助手、文件传输、版本化工单、广播受众和旧位置失效机制。
- 朋友的 localStorage/BroadcastChannel 业务状态改为现有 SQLite + SSE/轮询。业务数据不会因清空浏览器存储丢失；浏览器只保存界面偏好和模拟会话。

## 运行边界

这是本地 demo：航班、天气、邮件与转机均非真实服务。排程服务每2秒检查持久任务；服务关闭时不发送，重新启动后处理到期任务。SQLite事务使同一排程在并发检查时仅产生一条本地投递。生产邮件还需要真实发件渠道、幂等发件接口、重试/失败队列，当前未声称实现。

重置备份位于数据库同级 `demo-backups/`。恢复为全局演练数据操作，请在没有其他人编辑时进行。此轮开发的破坏性重置验证只在 `/private/tmp/twinomation-friend-integration-qa.sqlite3` 和 pytest 临时数据库执行。
